# Google Apps Script 보안 v9 설정

전체 절차와 주의사항은 **[보안 재배포 안내](../SECURITY_DEPLOYMENT.md)**를 먼저 읽으세요.

1. 기존 Google 스프레드시트와 코드를 백업합니다. 접수를 잠시 중단하세요.
2. 스프레드시트의 확장 프로그램 → Apps Script에서 Code.gs 전체를 새 파일 내용으로 교체합니다.
3. 편집기에서 initializeSecurity를 실행하고 본인의 Google 권한을 직접 승인합니다.
4. 프로젝트 설정 → 스크립트 속성의 ADMIN_KEY를 안전하게 보관합니다. 소스·QR·공개 저장소·채팅에 올리지 마세요.
5. 배포 관리에서 해당 배포를 '새 버전'으로 업데이트합니다. 익명 참석자 접속은 소유자 권한으로 실행 / 모든 사용자 접근을 사용하되, 새 서버 코드가 모든 데이터 요청의 권한을 검사합니다.
6. 사용하지 않는 모든 구버전 배포는 보관처리합니다. 새 배포를 추가하는 것만으로 기존 API가 차단되지 않습니다.
7. 웹 화면 파일도 같이 배포한 후 진행자 로그인 창에 /exec 주소와 관리자 키를 입력합니다.
8. 실제 명단 대신 가상 명단으로 휴대폰 QR 접속·서명 저장·접수 종료를 검증한 뒤 운영합니다.

## 기존 자료

기존 서버 레지스트리와 참석자 시트를 사용합니다. 파일을 교체한다고 기존 시트를 초기화하지 않습니다.
기존 브라우저 저장 자료는 자동 업로드하지 않습니다. 필요한 경우 화면의 '기존 로컬 자료 → 서버 복사'를 사용합니다.

## QR과 관리자 권한

- 기본 관리자/마스터 비밀번호는 더 이상 없습니다.
- QR은 연수별 24시간 유효하며 재발급 시 이전 QR은 무효화됩니다.
- '접수 종료'는 참석자 조회와 서명 접수를 차단하지만 기존 기록을 삭제하지 않습니다.
- 참석자는 다른 사람의 서명 원본·불참 사유를 받지 않습니다.
- 서명에는 서버 시각을 기록하지만 신원 인증이나 전자서명 인증서를 제공하지는 않습니다.

## 보관 및 삭제

setupCleanupTrigger를 직접 실행하면 생성일부터 30일 지난 묶음을 매일 정리합니다.
이번 코드 적용만으로 트리거를 새로 설치하지 않습니다. 기존 트리거가 있다면 계속 동작하므로 보관 정책을 확인하세요.
Google 시트 사본, 로컬 자료와 다운로드한 백업은 이 트리거가 삭제하지 않습니다.

## 통신

서버 키와 초대 토큰은 POST 본문으로 전송합니다. no-cors 전송 자체를 성공으로 간주하지 않고, 임의의 256비트 요청 번호로 서버 처리 결과를 확인합니다.
응답은 최대 90초 동안 캐시에 보관됩니다. Google 캐시·할당량 문제로 확인이 실패할 수 있으므로 오류 시 최신 자료로 저장 여부를 먼저 확인하세요.
